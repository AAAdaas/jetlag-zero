# JETLAG ZERO v3.0 | Your Flight Coach

iPhone Safari・PCブラウザで動く、GitHub Pages向けの無料・静的Webアプリです。日本語のUI、複数区間（最大6便）、自分の旅程を使った行動タイムラインと時差時計を備えています。サーバー・APIキー・有料契約は不要です。

## 使い方

1. 「旅程」から航空券の空港コード・現地日時を入力します（または初期値を利用）。
2. 日時は `YYYYMMDD HHMM`（例 `20261213 2155`）で直接入力、または右のカレンダーピッカーから指定できます。
3. 「この旅程でプランを作成」を押します。
4. 「いま」で出発地・目的地の2つの時計を確認できます。
5. **TIME MACHINE** のボタンやスライダーを使い、出発前に「機内」「乗り継ぎ」「到着後」をプレビューできます。プレビュー中は専用バナーが表示されます。「現在時刻に戻す」でリアルタイムに復帰します。
6. 「プラン」に各予定の現地時刻・出発からの経過時間・2都市の時刻を表示します。「機内」では乗継中を機内扱いしません。

## データ保持・旧版からの更新

- 旅程、準備チェック、睡眠メモはデバイスの `localStorage` に保存。写真や音声ファイルはアップロードしません。
- v2系で登録していた旅程があれば、可能な限り引き継ぎます。保存済みの旅程がある場合、初期サンプルは勝手に上書きしません。
- 不意のデータ消去に備え「旅程をバックアップ」からJSONを保存し、後で「バックアップを復元」できます。
- iPhoneのSafari・ホーム画面アプリは別々の保存領域になる場合があります。端末間の自動同期もありません。
- サウンドのノイズはオフライン生成、ローカル音声ファイルを選ぶことも可能です。ただしiOSのバックグラウンド・画面ロック中の連続再生は保証できません。
- OCRはTesseract.jsで**端末内で認識**します。エンジン・日本語と英語の言語データの最初のダウンロードにネット接続が必要です。旅程画像からの便名・日時抽出は補助機能で、必ず航空券と照合してください。

## 公開方法（GitHub Pages）

1. このZIPを解凍して、**ZIP内のファイル（フォルダごとではない）** を `AAAdaas/jetlag-zero` リポジトリのルートに置き、同名ファイルは置き換えてCommitします。
2. `Settings → Pages` を `Deploy from a branch` / `main` / `/(root)` に設定します。
3. `Actions` で公開が完了した後、 `https://aaadaas.github.io/jetlag-zero/` を開きます。
4. 以前の画面が見える場合はSafariを再読み込みしてください。v3では`sw.js`を更新し、バージョン別キャッシュで旧ファイルを削除します。

ファイル構成：`index.html`（画面）、`style.css`（見た目）、`engine.js`（日時・スケジュールの純粋計算）、`app.js`（画面操作・OCR・保存・音）、`sw.js`（オフライン対応）、`manifest.webmanifest`（PWA設定）、`icon.svg`・`icon-180.png`・`icon-512.png`（アイコン）。

## アルゴリズム・安全上の注意

- 予定イベントは**各区間の実際の出発時刻から到着時刻の間だけ**作成し、乗継イベントは乗継時間内、到着後は最終着陸後に作成します。
- `engine.js` はIANAタイムゾーン（日本・カタール・ドイツ等）を使い、日付変更・夏時間を考慮します。DSTの存在しない時刻はエラー、秋の重複時間は早い方を選択します。
- 機内睡眠は「最終目的地の普段の就寝〜起床時刻」が区間内にある場合にその重なる時間帯を提案します。体内時計の測定や医学的な個別最適化は行いません。
- 時差調整の基本方針はCDC Yellow Book 2026（[Jet Lag Disorder](https://www.cdc.gov/yellow-book/hcp/travel-air-sea/jet-lag-disorder.html)）を参考にした一般情報。特に時差が大きい時の**光の適切なタイミングは個人差が大きい**ため、特定の朝に強い光を浴びることを一律には推奨していません。
- 遅延、実際の離陸、搭乗開始時間、ゲート、位置情報、プッシュ通知とは連動していません。チェックインの締切・機内の安全指示は航空会社が最優先です。
- `.ics` 形式の主な予定をカレンダー用に出力できますが、読み込みはユーザーが行い、アラームの動作はカレンダーアプリに依存します。
